# 插件分类

插件库分为外设插件和应用插件。每个索引条目必须有一个 `group` 和一个 `category`；两个大类的“其他”分别独立。

| 大类 | group | 子分类 | category |
| --- | --- | --- | --- |
| 外设插件 | peripheral | 鼠标 | mouse |
| 外设插件 | peripheral | 键盘 | keyboard |
| 外设插件 | peripheral | 耳机 | headset |
| 外设插件 | peripheral | 手柄 | gamepad |
| 外设插件 | peripheral | 其他 | other |
| 应用插件 | application | 实验型应用 | experimental |
| 应用插件 | application | 测试型应用 | testing |
| 应用插件 | application | 其他 | other |

## 提交方式

在 `index.json` 的插件条目中增加分类，例如鼠标插件：

```json
{ "group": "peripheral", "category": "mouse" }
```

应用插件示例：

```json
{ "group": "application", "category": "experimental" }
```

这些字段是已有完整索引条目的补充，不能替代 ID、作者、版本、摘要和设备契约等字段。`scripts/update-index.ps1` 保留手工填写的分类，`scripts/verify-index.ps1` 和 CI 检查必填、合法子分类及与设备契约的一致性。

`kind` 保留其原有插件功能含义；不再使用它作为新条目的正式目录分类。`compatibility.scope: "device"` 的插件必须属于外设大类；`scope: "tool"` 的插件属于应用大类。目录分类不决定执行权限、设备兼容性或是否通过验收。

分类只存放于索引，不修改历史包内容，也不参与现有唯一编码计算。因此重新分类不会使同一包的设备验收记录失效。包、固件、手机 UI 声明发生变化时，仍按原有规则更新唯一编码。

## 主体界面和旧数据

主体插件库提供“外设插件”和“应用插件”两个入口，并分别提供全部及各子分类筛选。搜索和已安装插件同时受当前分类约束；切换大类会切回该大类的全部分类。无条目的分类显示“此分类暂无插件”。

兼容旧缓存及本地导入：旧 `kind: "audio"` 显示为“耳机”，`developer-tools` 显示在“应用插件 → 测试型应用”。已安装插件优先沿用当前索引中的分类；没有索引或分类的旧条目，按设备契约及旧 kind 回退，不能识别的应用归入“应用插件 → 其他”。

当前雷柏 VT3S MAX 位于“外设插件 → 鼠标”；H hub 开发者工具位于“应用插件 → 测试型应用”。未上架的类别保留空入口，不添加虚构插件。
