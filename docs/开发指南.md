# 开发者工具使用指南

## 准备环境

在支持插件 API 1.0 的 H hub 中导入并启用开发者工具，进入侧栏“开发者”。选择鼠标、键盘、音频或手柄环境，再建立项目。模板提供设计起点，不代表特定设备已兼容。

## 建议流程

1. **记录设备身份。** 填写插件 ID、名称、作者、版本，确认连接方式及 VID/PID。鼠标的有线、2.4 GHz 接收器和蓝牙可能对应不同通道，应分别记录型号、固件和设备版本。
2. **建立页面。** 使用预设控件，或修改控件 JSON、增加自定义按钮、填写自己的 HTML 页面。预览中的数值变化仅说明页面事件发生，不能作为设备配置成功的证据。
3. **采集对照报文。** 使用官方驱动，每次只改变一个参数，记录改变前后值。按工作台提示使用 USBPcap / Wireshark，导出带 `usb.capdata` 的 JSON，或 payload 列 CSV、十六进制文本，再分别导入前后报文。包中的导入逻辑限制单文件不超过 2 MB。
4. **比较候选差异。** 报文序号从 0 开始。选择相同设备与通道的前后报文，确认字节变化。差异只能给出候选字段，应使用多组参数重复验证字节序、范围、校验和通道身份。
5. **保存绑定。** 选择控件，设置字节偏移、宽度、字节序和基础报文，预览编码后保存绑定。编码预览不发送 USB 命令，也不会自动推断校验码。修改绑定后需重新完成协议验证。
6. **保存并导出。** 使用“保存项目文件”保留可恢复的 JSON，再完成验证记录并导出 `.hhub` 开发插件。页面本地保存不能代替项目文件备份。
7. **实现硬件逻辑。** 按宿主插件接口实现真实设备 Worker、权限接口、回读与断线恢复。通用开发包导出不代表硬件 Worker 已完成。
8. **真机验收。** 在目标型号、固件和连接方式下逐项验证写入、回读、重连、异常响应与参数边界，记录结果后再分发。

## 协议与素材来源

工作台包含官方驱动抓包和开源项目分析两种路线。若实际借用或改编上游代码，应保留对应许可证和来源记录；只有参考协议常量时也应记录研究来源和验证条件。不能把模板中显示的研究参考视为整个导出项目已有许可。

3.5 mm 耳机没有独立 USB 控制通道；音频端点控制与 USB 厂商协议是不同实现路线。无线设备需确认接收器和实际设备通道，避免混用报文。

## 提交插件前应说明什么

每个插件应附目标型号、支持固件与连接方式、插件 API 版本、权限及用途、已验证功能、未完成能力、安装步骤和已知问题。更新插件版本时同步更新索引和摘要，不要把未完成的宏执行或固件刷写写为已支持。
