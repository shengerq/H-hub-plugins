# 发布、更新与故障排查

## 发布仓库

1. 选择自己的 GitHub 仓库和分支。原附件建议名称为 `H-hub-plugins`、分支为 `main`；名称是建议，并不是既有远程仓库。
2. 上传本目录所有内容，确保 `index.json` 与两个 `.hhub` 位于根目录，且文件名大小写保持一致。不要额外套一层 `H-hub-plugins` 目录。
3. 在本地运行 `pwsh -File ./scripts/verify-index.ps1`。检查失败时先修复包与索引，再发布。
4. 上传后核对远程文件；在 H hub 中填写实际 `用户名/仓库名` 并同步插件库。
5. 用兼容主程序验证两个插件可下载、可导入，并分别进行需要的设备测试。

本仓库不保存 GitHub 凭据。若使用命令行发布，应使用自己的 GitHub 登录流程，避免将访问令牌写入 README、脚本或提交历史。

## 更新插件

1. 准备新版本 `.hhub`，核对其中的 ID、作者、名称及版本。
2. 更新索引中的版本、描述、相对文件名和 SHA-256。用 `Get-FileHash -Algorithm SHA256` 获取新摘要。
3. 若保留旧包供下载，可将它移入归档目录；索引只列出要提供的版本。
4. 运行校验脚本，更新说明与完整性清单，再提交变更。

`SHA256SUMS.txt` 记录本次整理时文件的摘要，修改文档、索引或包后需重新生成对应条目。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 同步插件库失败 | 核对用户名、仓库名、分支、网络和访问权限；确认根目录存在 `index.json` |
| 仓库只能看到 ZIP | 解压并上传索引及 `.hhub`，保留 ZIP 不能代替插件库文件 |
| 插件下载失败 | 检查索引的 `packageUrl`、文件名大小写、路径和分支 |
| 摘要或身份不匹配 | 比较实际 SHA-256 与索引，检查包中的 ID、名称、作者和版本；不要跳过校验 |
| 导入后没有入口 | 检查主程序是否兼容当前插件接口，以及插件是否安装并启用 |
| 鼠标未识别 | 确认 VT3S MAX 和 2.4 GHz 接收器，核对硬件 VID/PID、固件与连接状态；不要推断其他型号兼容 |
| 设置没有生效或通信超时 | 检查设备连接、宿主 HID 权限、型号和固件；记录回读与错误信息，不以页面数值变化作为成功依据 |
| 固件页面只能下载 | 当前设计未开放刷写；下载链接不代表插件可刷写 |
| 开发包无法直接控制硬件 | 导出的通用开发包仍需实现设备 Worker 等逻辑并验收 |
| 原 build-index.ps1 无法运行 | 它依赖原工程的上级 `dist`、`app` 目录；独立仓库使用本次新增的校验脚本 |
