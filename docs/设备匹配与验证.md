# 设备匹配与验证

主体库：[shengerq/H-hub](https://github.com/shengerq/H-hub)。主体程序通过本库根目录 `index.json` 同步插件；第三方作者通过 Pull Request 提交 `.hhub` 包、简介和索引。设备匹配指同一型号/硬件/固件的一类设备，不绑定序列号。

## 设备契约

包与索引必须包含相同的 `compatibility`。示例仅演示字段，固件号必须替换为实际读取的值：

```json
{
  "version": 1,
  "scope": "device",
  "deviceName": "设备准确型号",
  "hardwareId": "USB\\VID_1234&PID_5678",
  "firmwareVersions": ["实际固件版本"],
  "mobileUi": false
}
```

设备名称和固件号逐字匹配；硬件码统一大写。USB 使用 VID/PID；若同 VID/PID 存在不同硬件版本或传输协议，应加入明确的硬件版本/接口/传输区分字段到完整识别码中，由适配器提供相同值。禁止通配符、模糊固件范围以及用驱动版本或 USB 描述符版本冒充设备固件。未知固件填空数组，不能匹配任何固件。每个包只声明一个设备类别；多个明确固件可列在数组中。

非设备工具使用 `scope: "tool"`，名称和硬件码为空、固件列表为空、`mobileUi: false`，不参与设备匹配。

作者在 `description` 中填写功能简介。桌面端按“设备名称 · 识别码 · 固件 → 简介 → 作者 → 验证状态/手机 UI → 唯一编码”展示；简介不参与设备匹配或验证。

## 唯一编码和验证记录

`identityCode` 格式为 `HHUB1-` 加 64 位 SHA-256。编码绑定插件 ID、作者、插件版本、完整包 SHA-256 和标准化设备契约（包含手机 UI 声明）；`scripts/update-index.ps1` 生成编码并运行检查。编码位于索引中，避免把包摘要写回包造成循环摘要。修改包、固件或手机 UI 声明后编码改变，旧验证记录自动失效。发布修改包时必须增加插件版本，历史包保留。

**编码是可复核的身份标识，不是数字签名，也不能单独证明实机验收。** 主体库只有在所配置插件库的 `verificationRecords` 中找到完全相同编码的维护者验收记录时，才显示“实机已验证”。第三方作者不得自行批准实机或手机验收；由仓库维护者审核证据后合并记录。自定义插件源的验证标记只代表该源维护者的声明。

验证记录格式：

```json
{
  "identityCode": "HHUB1-对应完整编码",
  "reviewer": "实际审核维护者 GitHub 用户名",
  "reviewedAt": "实际审核时间，ISO 8601",
  "evidenceUrl": "https://实机测试报告链接",
  "hardwareVerified": true,
  "mobileUiVerified": true
}
```

报告需注明设备名称、完整硬件识别码、准确固件、插件版本和包摘要，并包含读取、写入、回读与断线恢复结果。`mobileUi` 表示作者声明实现手机 UI；`mobileUiVerified` 表示维护者已验收手机布局及实际控制，两者分开展示。支持手机 UI 不意味着手机测试通过。手机验收需同时通过实机验收，且包声明 `mobileUi: true`。

当前迁移的 0.5.2 包只补充契约元信息，功能代码延续 0.5.1。雷柏固件列表为空；手机 UI 尚未声明支持；`verificationRecords` 为空。历史的测试描述不能代替带准确固件和摘要的验收记录。

## 仓库维护

运行 `./scripts/update-index.ps1` 更新包摘要和编码，再运行 `./scripts/verify-index.ps1`。GitHub Actions 对提交及 PR 执行同样检查。CI 检查不能替代实机测试。

共享检查器 `scripts/PluginContract.cs` 与主体库 `source/PluginContract.cs` 保持一致。主体库 `Hhub.Catalog.exe --match request.json result.json` 接收 `indexUrl`、原始 `catalog` 与 `device`（`deviceName`、`hardwareId`、`firmwareVersion`），返回精确匹配的插件；固件未知、名称不同、硬件不同均不匹配。适配器需提供可信固件读数；本次不把现有旧 HID 路由或手机桥接自动改成已完成固件验收。

建议维护者在 GitHub 为主分支启用 PR 审核、必过 CI 和验证记录的 CODEOWNERS 审核。这些仓库保护设置需有管理员权限后另行配置；本次文件变更不宣称已启用这些设置。
